## 4. Known limitations (honest list)

**Not exercised / not built**

* **Live Anthropic provider** is type-checked and follows the documented tool loop, but has never run against the real API (no key was available). The demo provider is what was tested end to end, and it is labelled as such in the API and UI.
* **k6** load script not run; only the Node latency benchmark above was.
* **CI is untested on GitHub.** The workflow mirrors the commands that pass locally but has never executed on a runner.
* **No email delivery provider.** Verification and reset links are written to the backend log (`MailerService`) so the flows can be exercised locally; nothing is sent; wiring SMTP or an email API is a deployment task.
* **No Content-Security-Policy and no MFA.** Other security headers, CSRF, Argon2id, HttpOnly cookies and rate limits are in place (`backend/docs/SECURITY.md`).
* **No frontend lint step.** Next 16 removed `next lint`; the frontend is gated by strict `tsc`, tests and the build only. Adding ESLint is a follow-up.
* **No automated accessibility audit (axe) or visual-regression tests.** Accessibility was built to the rules in `frontend/docs/DESIGN_SYSTEM.md` and checked by keyboard-interaction component tests, not by a scanner.
* **`pnpm audit` is non-blocking in CI** (reports, does not fail).
* **BullMQ** behaviour is verified through the containerised stack and the E2E run, not by dedicated automated tests; unit/integration runs use the in-process fallback (ADR-0004).
* **Metrics/dashboards** (Prometheus, alerting) are not included; tracing, structured logs and health checks are (`infrastructure/monitoring/`).
* Dark theme only.

**Deliberate scope decisions**

* Predictions are statistical (trend and per-hour history) with an explicit sufficiency gate; below the threshold the API answers "not enough data" rather than a number. No machine-learning model is claimed.
* "Free" time exists only in the future, inside active hours. Untracked past time is `UNKNOWN`, never free (ADR-0003). New users therefore see mostly "unknown" until they track.
* Demo data is flagged (`isDemo`), isolated to the demo account, and removable without touching real data.

## 5. How to reproduce

```bash
docker compose up -d postgres redis
cd backend  && pnpm install && pnpm prisma:generate && pnpm prisma:deploy
            && pnpm typecheck && pnpm lint && pnpm test:unit && pnpm test:integration && pnpm build
cd frontend && pnpm install && pnpm typecheck && pnpm test && pnpm build
docker compose --profile apps up -d --build          # full stack on :3000 / :4000
cd frontend && npx playwright test                   # E2E against whatever is on :3000
node backend/scripts/bench.mjs                       # latency table above
```

Demo login (seeded, clearly marked): `demo@timeflow.app` / `demo-timeflow-2026`.
